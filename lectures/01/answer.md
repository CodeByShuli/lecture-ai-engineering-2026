## 宿題

### Basic Level
- やったこと： I asked Gemini the same question, "Explain recursion to a beginner using a simple example", three times using gemini-3.5-flash-lite and three times using gemini-3.8-flash. My goal was to compare the consistency, structure, and content of the responses generated by different models.

- 結果： Gemini Flash Lite successfully answered all three times, generating 562, 616, and 709 output tokens, with 11 input tokens each time. All three responses explained recursion using the analogy of people standing in a line. However, the explanations differed in length, wording, and code examples. The first two used Python, while the third used JavaScript. Gemini 3.8 Flash returned HTTP 503 errors in all three attempts, preventing a direct comparison between the models.

- 気づき・疑問： I noticed that even when using the exact same question and model, the responses were not identical. Although the main analogy remained consistent, the level of detail, programming language, and implementation of the recursive examples changed. One response also contained a small logical inconsistency in its analogy. This showed me that LLM responses can vary in both presentation and accuracy. I also learned that model availability can affect experiments, since the second model could not generate any responses.

### Implementation Level
- やったこと： I modified app/ask.py to support multi-turn conversations using client.chats.create() and chat.send_message(). I also added a --chat argument to enable interactive conversations directly from the terminal, without affecting the original functionality.
- 結果： I tested the implementation using gemini-3.5-flash-lite. I told Gemini that my name was Alice and that I had two cats. When I later asked it to recall that information, it correctly answered both questions. The conversation remained active until I manually exited.
- 気づき・疑問：I learned that individual API requests do not automatically share conversational context. By using a chat session, the model can maintain the conversation history and refer to previous messages. However, this memory only lasts for the current session and is not automatically saved between program executions.

### Advanced Level
- やったこと： I modified app/ask.py to measure API response time using time.perf_counter(), while keeping the existing input and output token counters. I tested two models, gemini-3.5-flash-lite and gemini-3.8-flash, using a simple question ("What is Python?") and a more complex question about supervised and unsupervised learning.
- 結果：Flash Lite answered the simple question in 2.58 seconds (5 input / 608 output tokens) and the complex question in 3.04 seconds (12 input / 855 output tokens). Flash 3.8 returned an HTTP 503 error for the simple question but successfully answered the complex question in 36.32 seconds (12 input / 876 output tokens). For the complex question, Flash 3.8 took almost 12 times longer than Flash Lite, despite generating a similar number of output tokens.
- 気づき・疑問： I noticed that response times can vary significantly between models, even when their token consumption is similar. The more complex question also required slightly more time and tokens with Flash Lite. However, a single successful run is not enough to determine which model is consistently faster. I also learned that free-tier rate limits vary by model. HTTP 429 errors generally indicate quota or rate-limit issues, while HTTP 503 errors usually indicate temporary service unavailability. This experiment showed me why measuring performance and documenting failed requests are important when evaluating LLM APIs.
